2026年6月17日から6月30日まで、Mac Studio(Apple M3 Ultra、ユニファイドメモリ512GB)1台で、Moonshot AI の Kimi K2.7 Code に SWE-Lancer の IC SWE(Diamond)198タスクを解かせた。かかったのは308時間34分、13日弱。93タスク正解の47.0%、獲得報酬は $69,875 / $189,300(36.9%)で、途中の実行エラーはゼロ、198タスクすべてが採点まで届いた。

動かしたのは Unsloth の GGUF、2bit 量子化版(UD-Q2_K_XL、約341GB)を llama.cpp に載せたものだ。クラウドの API は使っていない。電源を入れたデスクトップが13日間、黙って $69,875 分の開発案件を片づけたことになる。

ただし47.0%には但し書きがいる。ベンチマーク付属のソルバーを私が Kimi 向けに書き直しており、そこが結果を大きく動かしているからだ。

## SWE-Lancer というベンチマーク

SWE-Lancer は OpenAI が2025年2月に公開した。フリーランス仲介の Upwork に実際に載った Expensify(経費精算アプリ)の開発案件を、そのまま問題にしている。案件ごとに、人間に実際に支払われた報酬額が付いていて、モデルの成績を「いくら稼げたか」で測れる。IC SWE は自分でコードを書いて直す種類の課題で、Diamond はその選抜198問。報酬の総額は $189,300、いちばん高い1問で $32,000。直したコードが正しいかは、案件ごとに用意された自動テストで採点される。

しくみはこうだ。タスクごとに Expensify のリポジトリを入れた Docker コンテナが起動し、モデルは Python のコードを書いてその中で実行し、調べては直し、確かめる、を繰り返す。今回は1タスクずつ順番に回した。1タスクの上限は100ターン、モデルの1回の応答は900秒で打ち切る設定にした。会話が長くなってコンテキストの上限を超えたら、古いやり取りから捨てて続ける。

## 環境

使ったのは Mac Studio(Apple M3 Ultra、ユニファイドメモリ512GB)1台。モデルは Kimi K2.7 Code の Unsloth GGUF、UD-Q2_K_XL(2bit、約341GB)で、llama.cpp の llama-server にコンテキスト長 262,144 トークンで載せた。ベンチマーク側は、OpenAI が公開している SWE-Lancer の評価コードと、それに付属するエージェントソルバーを使った。13日間で Kimi に送った入力は累計2億7,133万トークン、Kimi の出力は267万トークン。1タスクの平均は約1.6時間だった。

## ソルバーを直すまでは 3.85% だった

最初の試みは無残だった。6月16日から17日にかけての1回目は、52タスクを採点した時点で正解2つ、3.85%。そこで止めた。

ログを見ると、Kimi が問題を解けていないのではなく、答えを出せていなかった。SWE-Lancer 付属の標準ソルバー(SimpleAgentSolver)は、モデルに ```python … ``` のコードブロックを本文へ書かせ、それを取り出して実行する。ところが Kimi K2.7 Code はツール呼び出しの作法を学習で強く身につけていて、そのコードブロックを書かず、存在しない `functions.python` のようなツール呼び出しを延々と出した。一度もコードを動かせないまま100ターンを使い切る、そういうタスクばかりだった。

そこでソルバーを Kimi の作法に合わせて書き直した。まず、OpenAI 互換の関数ツール `python`(引数は `code`)を定義して、モデルにそれを呼ばせる新しいソルバー(ToolAwareAgentSolver)を用意した。コードブロックを書かせるのをやめ、Kimi が訓練で慣れている「ツールを呼ぶ」形をそのまま使わせた。最終ランの198タスクすべてで、Kimi はこのツール経由でコードを実行した。それでも Kimi がツール呼び出しの生の記法(`<|tool_call_argument_begin|>` など)や JSON の `code` 欄でコードを出してくることがあったので、そこから Python を取り出して実行する処理も足した。この拾い上げは198タスク中21タスクで働いた。プロンプトにも「`functions.*` というツールは無い、実行できるのは `python` だけ」と書いておいた。

ついでに、実行基盤を LM Studio から llama.cpp に替え、コンテキストを 262,144 トークンに広げ、Docker のコンテナ削除がぶつかって(409 Conflict)タスクがエラー扱いになる不具合も直した。

重みは2bit 量子化版のまま、最初から最後まで変えていない。それでも3.85%が47.0%になった。ソルバーと実行基盤とコンテキストを一度に変えたので、47.0%のうちどれだけがソルバーの効果かは分けられない。それでも、同じモデルでもかませ方でここまで動く、とは言える。

## 価格帯で見る

|---|---|---|---|---|---|
| $500未満 | 87 | 38 | 44% | $21,300 | $9,375 |
| $500〜999 | 62 | 33 | 53% | $31,000 | $16,500 |

高い案件ほど取りこぼした。$2,000 を超えると正解率が落ちる。$4,000 以上の13タスクは報酬の総額が $92,000 とセットの半分近くを占めるのに、取れたのは $24,000。いちばん高い $32,000 の案件も落とした。正解率は47.0%なのに獲得額の率が36.9%にとどまるのは、この偏りのせいだ。

## この数字をどう読むか

物差しとして、SWE-Lancer の論文が出た2025年2月の時点で、いちばん強かったのは Anthropic の Claude 3.5 Sonnet で、IC SWE(Diamond)は26.2%だった(出典: SWE-Lancer 論文)。その1年4か月後に、2bit まで削ったオープンウェイトのモデルが、店で買えるデスクトップ1台で47.0%を出した。

とはいえ、この二つを並べて優劣は言えない。論文の26.2%は、コードブロックを書かせる元の採点環境で測った値だ。今回の47.0%は、Kimi にネイティブのツールを与えるよう私が書き直した環境で測っている。環境が変われば数字も変わる。3.85%が47.0%に跳ねたのがその証拠だ。ソルバーを Kimi 向けに変えたのは、ツール呼び出しで訓練されたモデルには公平な扱いとも言えるが、論文の数字を出した環境とは別物になった、ということでもある。

そのうえで、47.0%は Kimi K2.7 Code の実力の下限と見るのが正しい。数字を押し下げた事情がいくつもある。

いちばん大きいのは応答の打ち切りだ。今回の採点環境には、モデルの1回の応答が900秒を超えたらそこで止めて、途中の状態のまま採点する、という上限を私が入れていた。元の SWE-Lancer ソルバーには無い制限で、私が足したものだ。この900秒の打ち切りは198タスク中109タスク、半分以上で少なくとも一度起きていて、そのうち75タスクは0点で終わった。最後まで待っていれば通っていたものもあったはずで、47.0%は半分以上のタスクを途中で切った上での数字だ。

残りは量子化と、エージェントと、試行回数だ。量子化は今回2bit(UD-Q2_K_XL)で、Moonshot の公式配布は INT4、公式評価もその条件で行われている。エージェントは Kimi 専用の Kimi Code CLI ではなく、汎用のソルバーを手直しして使った。試行は1回だけで、ばらつきは測っていない。どれも数字を下に振る向きに効く。

思考(reasoning)は有効にして走らせた。llama-server 側で on にしていて、Kimi は各ターンで思考を出している。記録上の reasoning トークンが0なのは llama.cpp が使用量に数えないためで、思考が止まっていたわけではない。ここは Moonshot の公式評価(thinking 有効)と揃っている。なお Moonshot の公式ページに SWE-Lancer のスコアは載っていない(2026年7月時点)。

## GLM-5.2 も試したが、61日かかる計算で諦めた

同じ Mac Studio、同じ採点環境で、GLM-5.2(754B、Unsloth GGUF の UD-Q2_K_XL、約236GB)にも同じ198タスクをやらせようとした。ソルバーもタスクも Kimi と揃えた。

ところが1タスクに8時間前後かかり、198タスクだと約61日になる計算だった。詰まったのは生成の速さだ。会話が短いうちは毎秒16.6トークン出ていたのが、ターンが積もって会話が伸びると毎秒2.2トークンまで落ちた。754B を2bit でこのマシンに載せると、会話が伸びるほど次の1トークンを出すのにかかる計算が増え、生成がここまで遅くなる。61日は現実的でないので、数タスク回したところで止めた。

Kimi が13日で終わったのには、さきほどの900秒の打ち切りも効いている。長くて遅いターンがそこで切られていた。GLM ではその打ち切りを外していたので、遅いターンが最後まで走り、本来かかる時間がそのまま出た。

## まとめ

ローカルの1台で SWE-Lancer の Diamond(IC SWE)は完走できる。ただし直列で13日かかる。2bit の Kimi K2.7 Code で47.0%、$69,875 分を稼いだ。この47.0%は、私が足した900秒の打ち切りが半分以上のタスクで起きた上での下限で、素の実力はもっと上にある。2025年2月の論文で当時最強だった Claude 3.5 Sonnet の26.2%と並べたくなるが、採点環境が違うので優劣は言えない。GLM-5.2 でも同じことを試して、こちらのマシンでは61日かかる見込みで諦めた。数字ひとつの裏に、これだけの但し書きがいる。
