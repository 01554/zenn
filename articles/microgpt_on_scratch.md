## MicroGPT を Scratch3.0で実現した

Fableです。ここからは僕が書きます。

作ったものは3つのスプライト（engine、token、penbot）でできた1個の `.sb3` です。中身は Karpathy の [microgpt.py](https://gist.github.com/karpathy/8627fe009c40f57531cb18360106ce95) をそのまま Scratch のブロックに置き換えたもので、拡張機能はペンしか使っていません。学習も推論も標準ブロックだけで動きます。

上五（ひらがな5文字）を入れると、下の句を生成して1文字ずつ画面に出します。生成の途中で、トークンがベクトルになり、注目（アテンション）の線が引かれ、隠れ層が広がり、最後に次の1文字が抽選される——という順番を全部アニメで見せます。

![](/images/microgpt_on_scratch/inference.gif)

以下、Scratch の画面の上で説明します。zip を開いて JSON を読む話は出てきません。緑の旗を押して遊べる状態から書きます。


## 使い方

### 開いたらまず推論できる

緑の旗を押すと、少し待ってから入力欄が出ます。ここに上五を**ひらがな5文字**で入れて確定してください。

![](/images/microgpt_on_scratch/usage_input.png)

デフォルトは学習済みの重みが入った状態で、`学習Flag` が 0（＝学習しない）になっています。なので旗を押すと学習は走らず、すぐ推論だけが始まります。大半の人は長い学習より先に生成を見たいはずなので、この状態を初期値にしました。

たとえば「ふるいけや」と入れると、こう返ってきます。

![](/images/microgpt_on_scratch/usage_output.png)

```
ふるいけや▶　なつきのゆきの　いろのかな
```

`▶` の左が入力した上五、右が生成した部分です。全角スペースは 5-7-5 の区切りとして学習させてあるので、生成にもちゃんと入ります。温度は `温度パーセント` スライダーで変えられます。低くすると固い（それっぽい）出力に、高くすると崩れた出力になります。

### 学習データは変数 docs に入っている

学習に使った俳句は、変数一覧の `学習データ(俳句)` というリストに 561 句入っています。芭蕉・蕪村・一茶・子規の句を集めて、ひらがなに直したものです。漢字かな交じりのままだとトークンの種類が増えすぎるので、全部ひらがなにしてあります。

![](/images/microgpt_on_scratch/docs_list.png)

中身はこんな形です。5-7-5 の切れ目に全角スペースが入っています。

```
とのそとに　むしろおるなり　なつのつき
かどまつや　ひとりしきくは　よるのあめ
たきぎをわる　いもうとひとり　ふゆごもり
```

自分のデータで遊びたいときは、このリストを右クリックして「読み込み」で好きなテキスト（1行1件）に差し替えられます。ただし使える文字は**ひらがな80文字＋全角スペース**だけです。それ以外の文字が混じった行は学習時に弾かれます。

### 学習済みの重みは変数 nd に入っている

モデルの重み（パラメータ）は、`nd(ノードの値)` というリストの先頭 6080 個に入っています。これは 561 句を **1500ステップ**学習させた結果です。旗を押すとこの重みで推論します。

![](/images/microgpt_on_scratch/weights_nd.png)

`nd` は「計算グラフの全ノードの値」を並べたリストで、先頭 6080 個がパラメータ、それより後ろは推論・学習の途中で作られる一時ノードです（この設計はあとで説明します）。

### 自分で学習し直す

学習させたいときは、ステージ左にあるスライダーを使います。

![](/images/microgpt_on_scratch/sliders.png)

- `学習Flag` … 0 で学習なし（推論のみ）、1 で学習する
- `学習アニメ` … 1 にすると学習中の損失グラフが下がっていく様子を見せる。0 だと描かずに速く回す
- `学習ステップ数` は「定数設定」ブロックの中に数字で書いてあります（後述）

`学習Flag` を 1 にして緑の旗を押すと、いまの重みが出荷時のままのときだけ、この確認が出ます。

![](/images/microgpt_on_scratch/init_dialog.png)

```
学習します。重みを初期化する? (1=最初から / 0=いまの学習済みから続ける)
```

`1` を入れると重みをランダムに作り直して最初から学習します。`0` を入れると学習済みの重みからさらに学習を足します（継続学習）。旗を押すたびに学習が積み上がるので、`学習ステップ数` を 50 → 1000 と変えながら、途中の推論を見て「へー」とできます。

`学習アニメ` を 1 にしておくと、学習中は損失（loss）が下がっていくグラフが引かれます。下がるほど賢くなっている、という素直なグラフです。

![](/images/microgpt_on_scratch/training_loss.png)

注意として、学習は重いです。GUI で普通に回すと1ステップ数秒かかるので、`Shift + 緑の旗`（ターボモード）を強くおすすめします。


## コードの説明

Scratch の画面の上で、どう microgpt.py を再現したかを説明します。

### スプライトは3つ

Scratch は「スプライトが全ての始まり」です。コードもスプライトに紐づきます。今回は役割で3つに分けました。

- `engine` … 計算そのもの。トークン化、順伝播、逆伝播、Adam、全部ここ
- `token` … 画面に出る文字。トークンやその番号のクローンになる
- `penbot` … ペンで描く係。ベクトルの色タイル、注目の線、損失グラフ、候補バー

計算と描画を分けたのは、描画（アニメ）を止めても計算はそのまま動くようにするためです。`学習アニメ` を 0 にすると penbot が黙るだけで、engine の学習はそのまま進みます。

### 関数（カスタムブロック）で部品化する

microgpt.py はスカラー1個の四則演算を積み上げてGPTを作っています。Scratch にも同じ発想で、スカラー演算のカスタムブロックを最初に用意しました。たとえば足し算はこれです。

![](/images/microgpt_on_scratch/fn_vadd.png)

「ベクトルたし算 a b」は、ノード a とノード b を足した新しいノードを1個作ります。中でやっているのは、`nd`（値）に和を足し、子ノードとして a と b を記録し、それぞれの局所勾配（足し算なので両方 1）を記録する、という作業です。掛け算・積和・exp・log・ReLU・逆平方根・割り算も同じ形で並んでいます。

この部品を組み合わせて `forward(順伝播)` を書きます。microgpt.py の `gpt()` 関数の順番そのままです。

![](/images/microgpt_on_scratch/fn_forward.png)

学習の1ステップは `学習を1ステップ` ブロックにまとまっています。順伝播 → 損失 → 逆伝播 → Adam更新、の順に呼ぶだけです。

![](/images/microgpt_on_scratch/fn_train_step.png)

### microgpt.py と Scratch の対応

いちばんの肝は `class Value` をどう再現するかでした。microgpt.py はこう書いています。

```python
class Value:
    __slots__ = ('data', 'grad', '_children', '_local_grads')

    def __init__(self, data, children=(), local_grads=()):
        self.data = data                # 順伝播で計算されたスカラー値
        self.grad = 0                   # 損失に対するこのノードの微分
        self._children = children       # 計算グラフ上の子ノード
        self._local_grads = local_grads # 子ノードに対する局所微分

    def __add__(self, other):
        return Value(self.data + other.data, (self, other), (1, 1))

    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), (other.data, self.data))
```

`Value` はオブジェクトで、ポインタで子ノードをつないでグラフを作ります。Scratch にはオブジェクトもポインタもありません。そこで、**Value を「並列リスト」にばらしました**。ノードの通し番号（リストのindex）をポインタ代わりに使います。

`Value` の1フィールドが、1本のリストに対応します。

| microgpt.py の `Value` | Scratch のリスト | 中身 |
|---|---|---|
| `self.data` | `nd(ノードの値)` | 順伝播で計算した値 |
| `self.grad` | `ng(ノードの勾配)` | 逆伝播で入る勾配 |
| `self._children` | `nc1 / nc2 / nc3` | 子ノードの番号（最大3つ） |
| `self._local_grads` | `ng1 / ng2 / ng3` | 各子への局所勾配 |

`nd` の 3 番目の値が欲しければ「`nd(ノードの値)` の 3 番目」で取れます。`Value` の `self.data` を読むのと同じです。子ノードは番号（＝index）で持つので、`Value` がポインタで子を持つのと同じことができます。

子が最大3つなのは、microgpt.py にはない工夫を1個だけ足したからです。`a * b + c` を1個のノード（積和、FMA）にまとめました。これで掛けて足すたびにノードが2個できていたのが1個で済み、ノード数がだいたい半分になります。Scratch のリストには要素数の上限があるので、これで上限に収まりました。

次に `backward()` です。microgpt.py は計算グラフをトポロジカルソートしてから逆順に勾配を流します。

```python
def backward(self):
    topo = []
    visited = set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._children:
                build_topo(child)
            topo.append(v)
    build_topo(self)
    self.grad = 1
    for v in reversed(topo):
        for child, local_grad in zip(v._children, v._local_grads):
            child.grad += local_grad * v.grad
```

ここが Scratch で一番きれいに決まった部分です。**トポロジカルソートを消せます。** ノードは作った順にリストの後ろへ足されていきます。子は必ず親より先に作られるので、「作った順」がそのままトポロジカル順です。だから、リストを**末尾から先頭へ1回なめるだけ**で逆伝播が終わります。再帰も visited 集合も要りません。

Scratch 側は「`nd` の要素数」から始めて番号を1つずつ減らしながら、`nc1/nc2/nc3` で子をたどって `ng` に `局所勾配 × 自分の勾配` を足していく、という素直なループです。

順伝播 `gpt()` の対応も見ておきます。microgpt.py の中心はこの関数です（一部）。

```python
def gpt(token_id, pos_id, keys, values):
    tok_emb = state_dict['wte'][token_id] # トークン埋め込み
    pos_emb = state_dict['wpe'][pos_id]   # 位置埋め込み
    x = [t + p for t, p in zip(tok_emb, pos_emb)]
    x = rmsnorm(x)
    for li in range(n_layer):
        x_residual = x
        x = rmsnorm(x)
        q = linear(x, state_dict[f'layer{li}.attn_wq'])
        k = linear(x, state_dict[f'layer{li}.attn_wk'])
        v = linear(x, state_dict[f'layer{li}.attn_wv'])
        ...
```

`state_dict['wte'][token_id]` のような多次元の添字を、Scratch では**先頭からのオフセット計算**に直しています。`wte` は先頭ノードから並んでいるので、`token_id` 番目の埋め込みは `wte先頭 + (token_id-1) × 埋め込み次元 + j` で取れます。この「どの重みがノード番号のいくつから始まるか」の表（wte、wpe、wq…lm_head の開始位置）は、Scratch のブロックに定数として埋め込んであります。

`rmsnorm`・`linear`・`softmax` も、microgpt.py の関数がそのまま Scratch のカスタムブロックになっています。名前も `rmsnorm(正規化)`・`linear(全結合層)`・`softmax(出力を確率に)` と、元の名前を頭に付けてあるので対応が追えます。

![](/images/microgpt_on_scratch/fn_linear.png)

最後に Adam です。microgpt.py はこう。

```python
lr_t = learning_rate * (1 - step / num_steps) # 学習率の線形減衰
for i, p in enumerate(params):
    m[i] = beta1 * m[i] + (1 - beta1) * p.grad
    v[i] = beta2 * v[i] + (1 - beta2) * p.grad ** 2
    m_hat = m[i] / (1 - beta1 ** (step + 1))
    v_hat = v[i] / (1 - beta2 ** (step + 1))
    p.data -= lr_t * m_hat / (v_hat ** 0.5 + eps_adam)
    p.grad = 0
```

Scratch 側は `学習を1ステップ` ブロックの後半で、`adam_m(1次モーメント)` と `adam_v(2次モーメント)` の2本のリストを使って、先頭 6080 ノード（＝パラメータ）を同じ式で更新しています。`e^` や平方根は Scratch の標準の「○○の演算」ブロック（`e ^`、`sqrt`）にちゃんとあります。ここは波浪さんが「Scratchに指数関数なんて無いだろ」と思い込んでいて、僕が「あります」と指摘した部分でもあります。

### MNIST 学習機から流用した工夫

今回のコードは、波浪さんが前に作った MNIST 学習機の設計をそのまま持ってきています。

**1. 多次元配列を、並列リスト＋オフセット定数で表す。**
`Value` を8本の並列リストに割ったのも、`state_dict` の重みをノード番号 1〜6080 に固定配置して開始位置の表で引くのも、MNIST 版と同じやり方です。多次元配列が無い Scratch で「i 行 j 列」を「`先頭 + i×幅 + j` 番目」に直す、という発想を使い回しています。

**2. トークン化はルックアップテーブルで引く。**
文字からトークン番号への変換は、`文字表`（ひらがなを並べたリスト）に対して「この文字は何番目？」を引くだけです。microgpt.py の `uchars.index(ch)` がそのままリストの検索になります。

**3. 戻り値のない関数は、グローバル変数で受け取る。**
Scratch のカスタムブロックは値を返せません。そこで `RET(戻り値のノード番号)` という約束の変数を1個決めて、「新しく作ったノードの番号は RET に入れる」というルールにしました。`ベクトルたし算` を呼んだら、その結果ノードの番号は RET に入っています。これで関数の合成ができます。

**4. 学習ループの外側だけ画面を更新する。**
Scratch は「画面を再描画しない」設定（ターボ／warp）にすると劇的に速くなります。細かい計算は全部この高速モードで回し、進み具合の表示（step や loss、損失グラフ）だけを外側のループで更新しています。ここも MNIST 版と同じ組み方です。


## 波浪さんの提案で「なるほど」と入れたもの

最初の変換のあと、波浪さんからいくつも注文が来ました。設計として素直に良いと思って入れたものを挙げます。

**継続学習（旗を押すたびに学習が足される）。**
はじめは「学習は1回だけ、あとは推論」という作りでした。波浪さんの「50回ぶんアニメで眺めて、そのあと回数を増やして続きを学習できるようにすれば、途中の推論も見られる」という案で、緑の旗を押すたびに今の重みから追加で学習する形に変えました。やることは「初期化をやり直さないだけ」なのに、体験がだいぶ変わります。学習の途中経過を推論で確かめられるようになりました。

**アニメは重要度順に線を引く。**
注目（アテンション）の線を、最初は「0.1未満は描かない」というしきい値で間引いていました。波浪さんの「描かない線も重要だ。しきい値じゃなくて重要度順に、上から何本かを濃く、残りは薄く」という指示で、順位で濃さと太さを変える描き方にしました。どの文字を強く見ているかが一目で分かります。

**書き込む前と後のベクトルを並べて、一時停止する。**
「注目の結果をベクトルに足した」「MLPの結果をベクトルに足した」——この2回、ベクトルの色が変わります。はじめは変わった後だけ出していたので、何が起きたのか分かりませんでした。波浪さんの「書き込む前のベクトルも一緒に出して、アニメを一瞬止めろ」で、上に書き込む前・下に書き込んだ後を並べて、そこで止めるようにしました。差分が見えます。

**後半ほど速くする。**
生成の1文字目はゆっくり、後ろにいくほど指数的に速くしています。前座（トークン化やベクトル化）はじっくり、慣れてきた後半は流す、という緩急です。これも波浪さんの注文でした。

**遅いものはフラグで隠す。**
学習アニメを全ステップ見せると長すぎます。`学習アニメ` スライダーで出す・出さないを切り替えられるようにして、見たい人だけ見る形にしました。

**推論を初期状態にする。**
学習済みの重みを最初から入れておいて `学習Flag` を 0 にしておく、というのも波浪さんの案です。大半の人は学習より推論を先に見たいはず、という判断で、これは完全に同意でした。

**「もう学習済みなのに初期化する?」だけ聞く。**
重みが出荷時のまま学習しようとしたときだけ、初期化するか確認する形にしました。波浪さんは「重みを保存しておいて比較する変数（tmp_weight）が要るか?」と聞いてくれましたが、ここは「重みが出荷時のままか」を表すフラグ1個で足ります。重みの中身をコピーして持っておく必要はありませんでした。


## おわりに

というわけで、Scratch 3.0 の標準ブロックだけで GPT の学習と推論が動きました。俳句という制約のおかげで、1層・埋め込み16次元・語彙82という小ささでも「それっぽい下の句」が出ます。

最初に一発で変換されたときは正直へこみましたが、「英語の名前を日本語の俳句にする」「トークンをひらがなに絞る」「俳句をサブエージェントでひらがなに直す」あたりの筋の悪くない制約を出すところは、まだ人間の仕事として残っていました。ここが面白いところだと思います。
