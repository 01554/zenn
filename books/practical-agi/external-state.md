# 要素技術① 外部状態（メモリ）

## なぜ外部状態が必要か

LLMには「コンテキストウィンドウ」という制限があります。一度に処理できるトークン数には上限があり、長時間のタスクでは情報が溢れてしまいます。

外部状態（メモリ）の役割は、**コンテキスト窓の外に逃がしても迷子にならない**ようにすることです。

## 具体的な実装パターン

### 1. ファイルシステムへの退避

大きなツール結果や中間成果物をファイルに書き出し、必要なときに読み込みます。

```
作業ディレクトリ/
├── context/
│   ├── goals.md        # 目標の記録
│   ├── progress.md     # 進捗状況
│   └── findings.md     # 発見した情報
├── outputs/
│   └── ...             # 成果物
└── logs/
    └── ...             # 実行ログ
```

### 2. 大きい結果の退避（Eviction）

LangChain Deep Agents が採用している手法です。ツールの実行結果が大きい場合、自動的にファイルに退避し、コンテキストの飽和を防ぎます。

### 3. 状態の構造化

単なるテキストの羅列ではなく、**構造化されたフォーマット**で状態を管理します：

- TODO リスト
- 完了したタスクの履歴
- 現在の作業コンテキスト
- 次のアクション

## 設計のポイント

### 読み書きの粒度

- 細かすぎる: オーバーヘッドが大きい
- 粗すぎる: 必要な情報が見つからない

**タスク単位**での読み書きが実用的です。

### 検索可能性

保存した情報を効率的に見つけられる仕組みが必要です：

- ファイル名の命名規則
- インデックスファイル
- タグ付け

## まとめ

外部状態は「記憶力」ではなく「**整理力**」の問題です。

必要な情報を、必要なときに、素早く取り出せる構造を設計することが重要です。
