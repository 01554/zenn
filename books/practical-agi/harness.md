# 要素技術⑤ 運用ハーネス

## ハーネスとは何か

**ハーネス = 長期稼働を成立させる運用・足場** です。

エージェント本体（LLM）とは別に、エージェントを「支え、導き、管理する」仕組みがハーネスです。

## なぜハーネスが必要か

Anthropic は次のように問題を設定しています：

> 「長く走れるはずなのに前進できない」

理論上、エージェントは無限に続けられるはずです。しかし現実には：

- 進捗が止まる
- 目標からドリフトする
- 同じ失敗を繰り返す
- リソースを浪費する

これらの問題に対処するのがハーネスの役割です。

## ハーネスの構成要素

### 1. チェックポイント

定期的に状態を保存し、問題が発生したら復元できるようにします。

```
checkpoint/
├── state_001.json
├── state_002.json
└── state_003.json  ← 最新
```

### 2. 進捗監視

エージェントが実際に前進しているかを監視します。

- タスク完了率
- 時間あたりの成果
- エラー発生率

### 3. 完了条件の強制

「いつ終わるか」を明確に定義し、強制します。

- 目標達成
- タイムアウト
- リソース制限

### 4. 引き継ぎ機構

エージェントを再起動する際、コンテキストを適切に引き継ぐ仕組みです。

## Anthropic のハーネス設計

Anthropic は「Effective harnesses for long-running agents」で、以下の要素を挙げています：

1. **進捗の追跡**: エージェントが前進しているか
2. **引き継ぎ**: コンテキストの受け渡し
3. **検証**: 成果物の品質確認

## LangChain Deep Agents のハーネス

LangChain は Deep Agents を「agent harness」と呼び、以下を標準装備しています：

- Planning tools（計画管理）
- Filesystem tools（状態の永続化）
- Subagents（作業の委任）
- Large result eviction（コンテキスト管理）

## 「モデルが賢い」だけでは足りない

Cursor の実験からの結論：

> 「役割分離」や「Judge による継続判定」のような**システム設計**が重要

モデルの性能向上だけでは、長期稼働の問題は解決しません。ハーネスという**仕組み**が必要です。

## まとめ

ハーネスは「支える力」です。

エージェント本体がどれだけ賢くても、長期稼働を成立させるには**運用の足場**が不可欠です。
