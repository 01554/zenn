# 要素技術② 計画と分解

## なぜ計画が必要か

「長期視野」は気合いでは伸びません。

人間が複雑なプロジェクトに取り組むとき、まず計画を立て、タスクを分解し、優先順位をつけます。エージェントも同じです。

## タスク分解の重要性

大きなタスクを小さな単位に分解することで：

1. **進捗が測定可能**になる
2. **失敗の影響範囲**が限定される
3. **再開ポイント**が明確になる

## 実装パターン

### 1. TODO ツールの組み込み

LangChain Deep Agents は `write_todos` をツールとして組み込んでいます。

```markdown
## TODO
- [ ] 要件の確認
- [ ] 設計書の作成
- [x] 環境構築 ← 完了
- [ ] 実装
- [ ] テスト
```

タスク分解と進捗追跡を**ツールとして固定**することで、エージェントが確実に計画を立てるようになります。

### 2. Planner / Worker の分離

Cursor の実験で効果が実証された構造です：

| 役割 | 責務 |
|------|------|
| **Planner** | コードベースを探索してタスクを生成 |
| **Worker** | 割り当てられたタスクの完了に集中 |

Planner が継続的に探索してタスクを作り、Worker は実装に集中する。この分業により、大規模なスケーリングが可能になりました。

### 3. 再帰的な分解

大きなタスクは、さらに小さなサブタスクに分解できます。Planner が再帰的なサブプランナーを呼び出すことで、複雑なプロジェクトにも対応できます。

## 計画の更新

計画は一度立てたら終わりではありません。

- 新しい情報が得られたら更新
- 想定外の問題が発生したら再計画
- 完了したタスクはマーク

**計画は生き物**として扱う必要があります。

## まとめ

計画と分解は「先を見通す力」です。

どの程度まで仕組みにするべきか？答えは「**ツールとして強制する**」です。気合いや指示だけでは、エージェントは計画をサボりがちです。
