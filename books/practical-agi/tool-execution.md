# 要素技術④ ツール実行

## ツール実行の本質

「long-horizon」の実体は、**世界（環境）に作用して、結果を観測して、次を決める**ことです。

LLMが単独でテキストを生成するだけでは、実用AGIにはなりません。外部環境と相互作用する能力が必要です。

## 典型的なツールカテゴリ

### 1. ファイル操作

```
- ファイルの読み込み
- ファイルの書き込み
- ディレクトリの作成・削除
- ファイルの検索
```

### 2. コマンド実行

```
- シェルコマンドの実行
- ビルド・テストの実行
- Git 操作
```

### 3. Web アクセス

```
- Web ページの取得
- API の呼び出し
- 検索エンジンの利用
```

### 4. 専門ツール

```
- データベース操作
- クラウドサービス操作
- 外部サービス連携
```

## ツール設計のポイント

### 1. 明確な入出力

ツールの入力と出力は明確に定義します。曖昧さがあると、エージェントが誤用する原因になります。

### 2. エラーハンドリング

ツールは失敗することがあります。エラー時に**何が起きたかを明確に伝える**ことが重要です。

### 3. 副作用の管理

ファイルを書き込む、コマンドを実行するなど、**副作用のあるツール**は慎重に設計します。

- 実行前に確認を求める
- ロールバック可能にする
- ログを残す

## LangChain Deep Agents のアプローチ

LangChain Deep Agents は、以下のツールを標準装備としています：

- **Filesystem tools**: ファイル操作
- **Planning tools**: タスク管理
- **Subagent tools**: サブエージェントへの委任

これらを「長いワークフローを回すための構造」として組み込んでいます。

## Sequoia が挙げた具体例

Sequoia は「coding agents」を実用AGIの最初の例として挙げています。

コーディングエージェントは：
1. コードを書く（ファイル操作）
2. テストを実行する（コマンド実行）
3. エラーを確認する（結果の観測）
4. 修正する（反復）

このサイクルを自律的に回せることが、実用AGIの象徴です。

## まとめ

ツール実行は「行動する力」です。

**世界に作用し、結果を観測し、次の行動を決める**。このループがなければ、エージェントは「考えるだけ」で終わってしまいます。
