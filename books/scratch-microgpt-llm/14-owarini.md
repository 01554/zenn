## 通ってきた道

Scratch のブロックだけで、小さな GPT を丸ごと1つ、動かしきりました。振り返ると、これだけの道を歩いています。

- トークン化：文字を番号にした（第3章）
- 埋め込み：番号を16個の数値、つまり意味の座標にし、位置情報も足した（第4章）
- アテンション：やわらかい辞書引きで前の文字から情報を集め、4つの視点（マルチヘッド）と因果マスクで文脈を取り込んだ（第5・6章）
- MLP と残差：集めた情報を64個に広げ・ReLU で曲げ・16個に戻して練り、元のベクトルに足し戻した（第7章）
- 出力とサンプリング：ロジット→ソフトマックスで確率にし、温度つきのくじ引きで1文字を引いた（第8・9章）
- 自己回帰生成：それを繰り返して俳句を詠んだ（第10章）
- 学習：損失で悪さを測り、誤差逆伝播で勾配を求め、Adam で6080個の重みを磨いた（第11・12章）
- 自動微分エンジン：6本のリストと逆順スキャンで、`backward()` の中身を自作した（第13章）

LLM がやっているのは、掛け算と足し算、表引き、そして間違いを測って少しずつ直すことを、大量に繰り返すことです。規模がずっと大きくなるだけで、ChatGPT の中で起きていることの大枠は、この本で見たものと同じです。Scratch で1手ずつ触れたことで、その仕組みが自分でたどれる知識になっていれば、この本の役目は果たせました。

## このモデルと本物の違い

このモデルが省いていることも書いておきます。本物の LLM との差は、そのまま次に学ぶべきことの一覧になります。

| 項目 | このモデル | 本物の LLM |
|------|-----------|-----------|
| トークン化 | ひらがな1文字 | BPE などのサブワード |
| ブロック段数 | 1段 | 数十〜百段 |
| 埋め込み次元 | 16 | 数千〜1万超 |
| 位置の表現 | 位置埋め込み（足し算） | RoPE など回転で表す方式 |
| 正規化 | なし | LayerNorm / RMSNorm |
| 活性化 | ReLU | GELU / SwiGLU |
| 重みの数 | 6080 | 数十億〜 |
| 学習データ | 俳句 約700句 | Web 規模のテキスト |

段数を増やす、次元を増やす、正規化を入れる、位置表現を RoPE にする。これらはこの本で作った仕組みの上に足していける拡張です。参考書『ゼロから作る Deep Learning ❻ 大規模言語モデル編』は、まさにこれらを一段ずつ積み上げていく本です。この Scratch 版で全体をつかんだうえで読むと、数式が知っている顔に見えるはずです。

## ここから先へ：遊びの提案

手を動かして確かめられることは、まだたくさんあります。

- 温度を振ってみる：温度パーセントを 10 と 150 で比べる。低温の単調さと、高温の破綻を体感する（第9章）。
- 損失曲線を眺める：学習率を変えて、下がり方・発散のしかたを観察する（第12章）。
- ベクトルを見つめる：生成中、画面下の16個の丸がステップごとにどう書き換わるかを追う。アテンション後と MLP 後で、どこが動くか（第6・7章）。
- 注目の線を読む：どのヘッドが、どの文字に線を張るか。ヘッドごとの傾向を探す（第6章）。
- 別のコーパスで学習する：俳句を自分の好きな短い文の集まりに差し替えて、学習し直してみる。

どれも、数式を眺めるだけでは得られない発見があります。見えること、触れること、壊せること。それが Scratch で LLM を作る価値でした。

## さいごに

大規模言語モデルという名前は、いかにも近寄りがたい。でも分解してみれば、その一手一手は、Scratch のブロックで組めるほど素朴でした。大きさに惑わされず、仕組みを自分の手で確かめる。その一歩を、この小さな俳句モデルが手伝えたなら幸いです。
