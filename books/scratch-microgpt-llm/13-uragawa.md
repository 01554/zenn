この本ではずっと、順伝播でノードを記録し、逆順スキャンで勾配を出す、と言ってきました。この章では、その自動微分（autograd）エンジンの中身を、Scratch のリストのレベルまで開けます。Scratch で LLM を成立させているのは、この仕組みです。

## PyTorch の1行が、Scratch では何になるか

PyTorch なら、

```python
loss.backward()
```

の1行で全重みの勾配が求まります。裏では、各テンソルが自分がどの演算から生まれたかを覚えた計算グラフを作り、それを逆にたどっています。Scratch にはこの仕組みがありません。そこで、計算グラフを生のリストとして自分で作ります。

## 1つの数値が1つのノード

このエンジンでは、計算に登場するすべての数値をノードとして扱います。重みも、途中結果も、最後の損失も、全部ノードです。ノードは通し番号を持ち、その番号がリストの何番目かと一致します。番号がそのままポインタになります。

各ノードについて覚えておきたい情報は、次の6つです。これを6本の並列リストで持ちます（$i$ 番目のノードの情報が、6本すべての $i$ 番目に入っている）。

| リスト | 役割 |
|--------|------|
| `nd` | ノードの値（順伝播で計算された数値） |
| `ng` | ノードの勾配 $\dfrac{\partial L}{\partial \text{nd}}$（逆伝播で埋まる） |
| `nc1` | 親ノード1の番号（この値を作った材料その1） |
| `nc2` | 親ノード2の番号（材料その2） |
| `ng1` | 親1へ勾配を渡すときの掛け率（局所微分） |
| `ng2` | 親2へ勾配を渡すときの掛け率 |

たとえば掛け算ノード $c = a \times b$ を作るときは、`nd` に $a b$ の値を積み、`nc1`=$a$の番号、`nc2`=$b$の番号、そして $\dfrac{\partial c}{\partial a}=b$ なので `ng1`=$b$の値、$\dfrac{\partial c}{\partial b}=a$ なので `ng2`=$a$の値、を一緒に記録します。値と親と親へ渡す掛け率を、演算した瞬間に同時に書き留めます。

:::message
実際のこのモデルでは、`a*b + c`（積和, FMA）のような3入力の演算を1ノードで表せるよう、親を3つまで持てる拡張（`nc3`/`ng3`）も入れてあります。ノード数が減って、Scratch でも動く規模に収まります。考え方は2親版とまったく同じです。
:::

## 順伝播：ノードを積んでいく

順伝播は、演算するたびに新しいノードをリストの末尾に追加していく作業です。掛ける・足す・ReLU・log……どの演算にも、値を積むことと親と掛け率を積むことがセットになった専用ブロックを用意してあります。

いちばん基本の、ベクトルどうしの足し算を見てみましょう。

![vadd（ベクトルの足し算）の定義](/images/microgpt_on_scratch/fn_vadd.png)

16個の成分を1つずつ足し、それぞれ足し算ノードとして記録しています。足し算 $c=a+b$ の局所微分は $\dfrac{\partial c}{\partial a}=\dfrac{\partial c}{\partial b}=1$ なので、掛け率はどちらも1です。

もう少し複雑な、行列とベクトルの掛け算（線形変換）はこうです。

![linear（線形変換）の定義](/images/microgpt_on_scratch/fn_linear.png)

掛けて足すを成分ぶんループするだけです。PyTorch の `W @ x` に相当する処理が、Scratch では掛け算ノードと足し算ノードを大量に積む二重ループになります。派手さはありませんが、ここで積まれたノード列が、そのまま逆伝播の道筋になります。

これらの部品を組み合わせて、順伝播の本体（アテンション→MLP→出力）が構成されます。

![forward（順伝播）の定義](/images/microgpt_on_scratch/fn_forward.png)

順伝播が終わると、`nd` には重み6080個の後ろに、その回の計算の全途中結果がノードとして積み上がっています。

## 逆伝播：後ろから前へ、一度スキャンするだけ

ノードは必ず、親（材料）が先、子（結果）が後、の順で積まれます。つまり `nd` の並びは、はじめからトポロジカル順序になっています。だから逆伝播は、

1. 全ノードの勾配 `ng` を0にリセット。
2. 損失ノード（最後のノード）の勾配 `ng` を 1 にする（$\dfrac{\partial L}{\partial L}=1$）。
3. `nd` を末尾から先頭へ1つずつ見ていく。各ノード $i$ について：
   - 自分の勾配 `ng[i]` を、親へ配る。
   - 親1へ：`ng[nc1[i]]` に `ng[i] × ng1[i]` を足し込む。
   - 親2へ：`ng[nc2[i]]` に `ng[i] × ng2[i]` を足し込む。

これだけです。連鎖律 $\dfrac{\partial L}{\partial \text{親}} = \dfrac{\partial L}{\partial \text{自分}}\times\dfrac{\partial \text{自分}}{\partial \text{親}}$ が、`ng[i]` × 掛け率を親に足す、という1行にそのまま対応しています。

なぜ後ろから前へ1回で正しいのか。あるノードの子は必ず自分より後ろにいるので、後ろから進めば、自分の番が来たときには自分に流れ込む勾配はすべて集まり終えています。だから再帰も、依存関係の解決もいりません。リストを逆順に舐めるだけで、数学的に正しい誤差逆伝播になります。

スキャンが終わると、`ng` の先頭6080個に、6080個の重みそれぞれの勾配 $\dfrac{\partial L}{\partial w}$ が入っています。あとは第12章の Adam でこれを使うだけです。学習ステップの中身を1枚にすると、こうです。

![train_step（1ステップの学習）の定義](/images/microgpt_on_scratch/fn_train_step.png)

順伝播 → 逆順スキャン → Adam 更新 → ノードの片づけ、という第11・12章で見た流れが、そのままブロックになっています。

## なぜこの設計が効くのか

この6本リスト方式のうまさを、あらためて並べます。

- ポインタがリスト番号。オブジェクトも参照も持てない Scratch で、計算グラフを表現できる。
- 記録順が計算順であり、トポロジカル順序。ソートも探索もいらない。
- 逆伝播が逆順スキャン。再帰なしで連鎖律が回る。Scratch は再帰が苦手なので、これが効く。
- 勾配は足し込み。1つのノードが複数の子に使われても（分岐）、各子からの寄与が自然に合算される。

PyTorch の autograd が内部でやっていることを、リスト6本に切り詰めたものが、このエンジンです。`backward()` の中身は、これくらい素朴な仕組みでできています。
