## 出力を入力に戻す

ここまでの第3〜9章は、すべて次の1文字を1個だけ出す計算でした。俳句を完成させるには、これを繰り返します。

> 生成した1文字を、入力の末尾にくっつけて、また次の1文字を出す。

出力を入力へ戻して回すので、自己回帰（autoregressive）と呼びます。自分の出力をもとに自分が進む、という意味です。

```
「ふるいけや」        → 予測 → 「あ」   → 継ぎ足す
「ふるいけや＋あ」    → 予測 → 「ま」   → 継ぎ足す
「ふるいけや＋あま」  → 予測 → 「に」   → 継ぎ足す
「ふるいけや＋あまに」→ 予測 → 「お」   → 継ぎ足す
        …                              …
```

これを、5・7・5 の17音（＋区切り）ぶん繰り返せば、俳句1句のできあがりです。冒頭の GIF が1文字ぶんだったのに対し、これはそれを何度も回した全体像にあたります。

## 条件付き確率の連鎖

自己回帰は、文全体の確率を1文字ずつの条件付き確率のかけ算に分解していることに対応します。

$$
P(c_0 c_1 \cdots c_{n}) = \prod_{k} P(c_k \mid c_0, c_1, \dots, c_{k-1})
$$

右辺の各因子 $P(c_k \mid \text{それまでの文字})$ は、第8章でソフトマックスが出した確率です。モデルは毎ステップ、これまでを条件にした次の確率を出し、そこから1文字引いて、条件を1つ伸ばします。その繰り返しです。

## プロンプトと続きを書く段階

ユーザーが入れた「ふるいけや」をプロンプト（prompt）と呼びます。自己回帰生成は、プロンプトの扱いで2段階に分かれます。

1. プロンプトを読み込む段階：与えられた「ふるいけや」を順に食べ、内部状態（各文字のベクトルとキー・バリュー）を作る。
2. 続きを書く段階：最後の文字から次を予測し、以後は自分の出力をプロンプトに足しながら回す。

ChatGPT に質問すると、まず質問文を読み込んでから、答えを1文字（1トークン）ずつ書き始めます。この読み込みと書き出しの2段構えは、このモデルでも同じです。

## ループとして書く

Scratch では、自己回帰は素直な繰り返しブロックです。

- 「生成した文字列」を保持する変数を用意
- 「まだ長さが足りない間」ずっと繰り返す
  - これまでの文字列で第3〜9章の計算を回して次の1文字を得る
  - その文字を「生成した文字列」の末尾に足す
  - ペンで1文字ぶん右に進めて描く

生成が進むほど、画面左のひらがなが1文字ずつ伸びていきます。最後まで回すと、こうなります。

![生成結果：ふるいけや▶　あまにおとしの　あきのうえ](/images/microgpt_on_scratch/usage_output.png)

「ふるいけや」に続けて「あまにおとしの　あきのうえ」。第9章までで見た1文字ずつの予測を、17音ぶん積み重ねた結果です。芭蕉の名句ではありませんが、5・7・5 のリズムに乗った、それらしい日本語になっています。

## KVキャッシュ：同じ計算を2度しない工夫

自己回帰には無駄があります。「ふるいけや＋あ」を計算するとき、「ふるいけや」の部分のキー・バリューは前のステップですでに計算済みなのに、素朴に書くと毎回ゼロから作り直してしまいます。

そこで、過去の文字のキー・バリューをとっておいて使い回すのがKVキャッシュ（KV cache）です。新しく増えた1文字ぶんだけ計算すればよくなり、速くなります。本物の LLM が長い文章をスラスラ出せるのも、この工夫があるからです。

:::message
このモデルも KV を保持しますが、Scratch という制約もあり、生成が進むほど計算量は増えていきます。GUI 上で下五まで律儀にアニメーションさせると、後半の1文字に数分かかることもあります。「本物でも、長い文章の生成は後半ほど重い」という感覚を、身をもって味わえます。
:::

## 推論のまとめ

ここまでで、学習済みのモデルが文章を生成するしくみ（推論）を、入口から出口まで通しで見ました。トークン化 → 埋め込み → アテンション → MLP → 出力 → サンプリング → 繰り返し。LLM が動いているときにやっているのは、これで全部です。

でも、まだ大きな謎が残っています。アテンションの $W_Q$、埋め込み表 $E$、MLP の $W_1$……あの6080個の数値は、どうやって決まったのか。最初はデタラメだったはずです。次章からは、モデルが自分で重みを学習するしくみに入ります。
