## 重みつき足し算の限界

重みつき足し算を2段重ねると、どうなるか。1段目の結果に、また掛け算して足すだけなので、全体をまとめると結局1段の重みつき足し算に整理できてしまいます。何層重ねても、1層ぶんの力しか出ません。

そこで、層と層のあいだに、まっすぐでない変換を1回はさみます。このモデルで使うのはシグモイド（sigmoid）という関数です。

```
sigmoid(z) = 1 ÷ (1 + exp(−z))
```

シグモイドは、どんな数を入れても 0 と 1 のあいだの数を返します。

| 入れる数 z | 出てくる数 |
|-----------|-----------|
| −10 | 0.00005 |
| −2 | 0.12 |
| 0 | 0.5 |
| 2 | 0.88 |
| 10 | 0.99995 |

大きなプラスは 1 の近くへ、大きなマイナスは 0 の近くへ押しつぶされます。ニューロンの答えが「ほぼ反応しない（0寄り）〜強く反応する（1寄り）」に揃うので、次の層が扱いやすくなります。

式を見ると、割り算と足し算のほかに `exp(−z)` が入っています。ここが問題です。

## 計算できない関数 exp

exp(x) は「2.718…という決まった数を x 乗した数」です。exp(1) = 2.718、exp(2) = 7.39、exp(0) = 1、exp(−1) = 0.368。x が整数なら掛け算の繰り返しですが、exp(2.934) のような中途半端な数が必要になります。これは足し算と掛け算の有限回のループでは出せません。

近似計算のテクニックはありますが、むずかしいうえに、Scratch で組むと遅い。そこでこの作品は正面突破をやめました。

**計算しない。答えを先に全部用意しておく。**

exp が必要になる x の範囲はせいぜい −10 から 10 です（シグモイドはその外ではもう 0 か 1 に張りついているので、範囲の端でつぶして問題ありません）。この範囲を 0.001 刻みにすると 20001個。exp の答えを Python に20001個計算させて、Scratch のリストに読み込んでおけば、あとは「何番目かを計算して表を見る」だけです。表引きに必要なのは引き算と掛け算だけ、つまり Scratch にもできる計算だけです。

## 手順1：Python で答えの表を作る

```python
import math

# exp の表：-10.0 から 10.0 まで 0.001 刻み → 20001行
with open("exp_table.txt", "w") as f:
    for i in range(20001):
        x = -10.0 + i * 0.001
        f.write(f"{math.exp(x):.15f}\n")
```

実行すると、1行に1つ答えが書かれたテキストファイルができます。exp の計算式を知らなくても、`math.exp` の1行が全部やってくれます。

## 手順2：Scratch のリストに読み込む

Scratch 側で `exp_table` という空のリストを作り、ステージに表示します。表示されたリストを右クリックすると「読み込み」メニューが出るので、さっきの exp_table.txt を選ぶだけです。

![リストを右クリックして読み込みを選ぶ](/images/mnist_predictor_on_scratch/step21.png)

20001行が一気に入ります。この読み込みはマウス操作でしかできないので、プロジェクトを作るときに1回だけ手でやります（一度読み込んでプロジェクトを保存すれば、リストの中身ごと保存されます）。

## 手順3：何番目を見るかを計算する

exp(x) が欲しいとき、見るべき行の番号はこう出ます。

```
番号 = (x − (−10)) × 1000 + 1
```

x = −10 なら1番目、x = 0 なら10001番目、x = 2.934 なら 12.934 × 1000 + 1 = 12935番目。0.001 刻みで並べたので1000倍すれば行番号に変わる、という理屈です。最後の +1 は、Scratch のリストが1番目から始まるからです。

x = 2.9348 のように刻みより細かい数が来ると、番号が 12935.8 のような小数になります。ふつうの言語ならエラーですが、Scratch はリストの何番目かに小数を渡すと勝手に切り捨てて整数にしてくれます。この作品はその仕様に乗っかって、丸め処理を書かずに済ませています。行儀は悪いですが、動きます。

## 手順4：範囲の外は端でつぶす

−10 より小さい x や 10 より大きい x が来たら、表を引く前に −10 と 10 に置き換えます。これが実物のブロックです。

![exp ブロックの定義。範囲チェックをしてから表を引く](/images/backpropagation_on_scratch/util/exp1.png)

上の2つの「もし」が範囲チェック、その下の1行が番号の計算、最後の1行が表引きです。exp の中身はこれで全部です。

動作確認。適当な値を入れて、本当の exp と見比べます。

![exp ブロックの動作確認コード](/images/backpropagation_on_scratch/util/exp2.png)

![表から返った値。0.001刻みの誤差の範囲で正しい](/images/backpropagation_on_scratch/util/exp3.jpg)

小数のままの番号でも正しい値が返っています。誤差は刻み幅ぶん、つまり 0.1% 未満で、この用途には十分です。

## log も同じ手で

第10章で log（ログ）という関数も必要になります。log(p) は「exp の逆」、つまり「exp(何) = p になるかの、何」です。これも同じ手で表にします。

必要になるのは p が 0 から 1 の範囲だけ（確率に対してしか使わないので）。0.0001 刻みで10001個です。

```python
# log の表：0 から 1.0 まで 0.0001 刻み → 10001行
with open("log_table.txt", "w") as f:
    f.write("-27.631021\n")          # log(0) の代役（下の説明を読んでください）
    for i in range(1, 10001):
        p = i * 0.0001
        f.write(f"{math.log(p):.15f}\n")
```

1行目だけ手で書いています。log(0) は「exp(何) = 0 になる何」ですが、exp はどんな数を入れても 0 にはならないので、log(0) という数は存在しません（限りなく大きなマイナス、と思ってください）。表の先頭には、かわりに十分大きなマイナスの数を入れておきます。

## sigmoid を組み立てる

exp が表で引けるようになったので、シグモイドは四則演算だけで組めます。

![sigmoid ブロックの定義。exp を呼んで 1÷(1+exp(−z)) を計算する](/images/backpropagation_on_scratch/util/sigmoid1.png)

![sigmoid の動作確認](/images/backpropagation_on_scratch/util/sigmoid3.jpg)

`p_z_val` に −1 を掛けて exp ブロックに渡し、返ってきた値で `1.0 ÷ (1.0 + exp の結果)` を計算しているだけです。

## この手はどこまで使えるか

:::message
じつは、Scratch の演算カテゴリにある「絶対値▼」ブロックのドロップダウンには、e^（exp のこと）も log も入っています。それを使えば表は要りません。それでもこの表引きを覚える価値はあります。この手はどんな関数にも効くからです。sin でも、ルートでも、ブロックに存在しない関数でも、「Python で計算 → テキストで書き出し → リストに読み込み → 番号を計算して引く」の4手で Scratch に持ち込めます。計算式を理解してから作るのではなく、答えの表を持ってきて先に動かす。わからない数学で手が止まったときに使える、実戦的な方法です。
:::
