## 学習の作戦

ここからが後半戦、学習です。作戦を先にぜんぶ書いておきます。

1. 画像を1枚見せて、答えを出させる（順伝播。もうできている）
2. どれくらい外したかを1つの数にする（損失。この章）
3. その外れの責任を、1662個の重みそれぞれに割り出す（逆伝播。第10〜11章）
4. 責任のぶんだけ各重みを少し動かす（更新。第13章）
5. 1に戻る。600枚 × 10周ほど繰り返す

「外れを数にする → 責任を割る → 少し直す」。この3拍子を7000回近く繰り返すだけで、デタラメな乱数だった重みが、数字を読める重みに育ちます。

## 正解につけた確率だけを見る

順伝播の結果は10個の確率でした。答え合わせで見るのは、そのうち1個だけです。正解が 3 の画像なら、モデルが 3 につけた確率。これが 1 に近いほど良い答えです。

この確率から損失（loss）という「悪さの点数」を作ります。作り方は、第5章で表にした log を使って、

```
損失 = −log(正解につけた確率)
```

数字で感覚をつかみます。

| 正解につけた確率 | 損失 |
|----------------|------|
| 1.0（完璧） | 0 |
| 0.5 | 0.69 |
| 0.1（お手上げ） | 2.3 |
| 0.01（大外し） | 4.6 |

当てれば 0、外すほど大きくなります。しかも大外しには急激にきびしくなります。0.1 と 0.01 は確率としては 0.09 しか違いませんが、損失は倍になります。自信満々で間違えると重い罰がつく採点方式です。

学習前のこのモデルは全数字に約 0.1 をつけるので、損失はだいたい 2.3 から始まります。この数字を覚えておいてください。学習がうまくいっているかを見分ける目印になります。

## ブロックはたった3行

![s5_calc_loss の定義](/images/backpropagation_on_scratch/fwd/s5.png)

1. `activations` の「出力層の開始位置 + 正解ラベル」から、正解につけた確率を取り出す
2. log の表を引く
3. −1 を掛ける

log の中身を計算できなくても、表があるので3行で済みます。正解ラベルは 0〜9、出力層の開始位置は209番目なので、たとえば正解が 3 なら 209 + 3 = 212番目を見ます。

:::message
第5章で log の表の先頭に −27.6 を入れておいたのがここで効きます。モデルが正解に確率 0 をつけてしまったとき、本当の log(0) は存在しませんが、表引きなら「損失 27.6」というとても大きな罰として処理が続きます。学習の途中で計算が止まらないための保険です。
:::

## 損失が下がる様子

この作品は、エポックごとに600枚の損失の平均を `epoch_loss_list` に記録します。実際の学習でこのリストがどうなったか、保存されている記録を見ます。

```
1エポック目   2.35
5エポック目   2.09
10エポック目  1.76
15エポック目  1.39
20エポック目  0.96
23エポック目  0.78
```

最初は 2.3 付近、つまり「10個の数字ぜんぶお手上げ」から始まって、じわじわ下がっていきます。学習が回っている画面では、こういう動きに見えます。

![エポックが進むたびに epoch_loss_list に平均損失が積まれていく](/images/debug_backpropagation/epoch2.gif)
