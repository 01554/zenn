## 196個の数から10個の数へ

このモデルがやることは、突きつめると「196個の数を受け取って、10個の数を返す」です。

- 入るもの：手書き数字の画像。14×14のマス目を左上から右へ1列ずつ読んだ、196個の 0 か 1（白なら0、黒なら1）。
- 出るもの：10個の確率。「0 である確率、1 である確率、……、9 である確率」。いちばん大きいものがモデルの答え。

196個から10個へ、一気には変換しません。あいだに2つの層をはさみます。

```
196個（入力）→ 8個（隠れ層1）→ 4個（隠れ層2）→ 10個（出力）
```

数が段々と絞られていきます。196個のマス目の情報が、8個の数に要約され、4個に要約され、最後に10個の確率になります。それぞれの矢印の正体は第4章でやりますが、中身はぜんぶ掛け算と足し算です。

この 196・8・4・10 という構成は、`LAYER_SIZE_LIST` というリストに入っていて、あとから自由に変えられます（第14章で遊びます）。

![モデル定義のブロック。LAYER_SIZE_LIST に 196, 8, 4, 10 を入れている](/images/debug_backpropagation/layer.png)

## 「学習する」とはどういうことか

矢印の中身の掛け算には、重み（ウェイト）という数が使われます。このモデルの重みは、あとで出てくるバイアスという仲間も入れて全部で1662個。最初はデタラメです（−0.1 から 0.1 のあいだの乱数で埋めます）。デタラメな重みで変換された答えは、当然デタラメです。

学習とは、この1662個を少しずつまともな値に直していく作業です。1枚の画像について、やることは5つ。

1. 画像1枚を読み込む
2. 順伝播：196個 → 8 → 4 → 10 と変換して答えを出す
3. 損失を計算：正解とどれくらいズレたかを1つの数にする
4. 逆伝播：そのズレの責任を、1662個の重みそれぞれに配る
5. 更新：責任のぶんだけ、各重みを少し動かす

実物の Scratch でも、この5つがそのまま5個のブロックになっています。

![train_one の定義。画像読み込み→順伝播→損失→逆伝播→重み更新](/images/backpropagation_on_scratch/bwd/全体.png)

この `train_one`（1枚ぶんの学習）を、600枚の画像に対して繰り返します。600枚ぜんぶを1周することをエポックと呼びます。10エポック、つまり同じ600枚を10周も見せると、重みはかなりまともになります。

## スプライトの分担

Scratch のコードはスプライトに書きます。この作品は6つのスプライトで分担しています。

| スプライト | 仕事 |
|-----------|------|
| 初期化 | モデルの形を決め、重みを乱数で用意する |
| predict | 本体。順伝播・逆伝播・学習ループのほぼ全コード |
| 入力スプライト | 14×14のマス目パネル（第3章） |
| sample | 学習画像をランダムに1枚、パネルに表示する確認窓 |
| reset | パネルを白に戻すボタン |
| Sprite1 | 学習中に使い方をしゃべる解説係 |

コードは分かれていますが、データは分かれていません。重みも途中の計算結果も、ぜんぶステージ上のグローバルなリストに置いてあり、どのスプライトからも読み書きできます。Scratch の関数（ブロック定義）には戻り値がないので、計算結果はリストや変数に書き込んで受け渡します。この作品の作りの大半は、この制約から決まっています。

## 動かし方

緑の旗を押すだけです。旗を押すと「初期化」スプライトが重みを乱数で作り直し、「学習開始」のメッセージを送ります。predict スプライトがそれを受けて学習ループを回し、終わるとテスト画像100枚で正解率を測って `p_accuracy` に入れます。0.25 なら正解率25%です。

学習中は Sprite1 が操作方法をしゃべり続けます。旗を押した直後のステージはこうなっています。

![旗を押した直後。損失リストが空になり、1エポック目が始まる。右下で Sprite1 が解説中](/images/scratch-mnist-backprop/stage_training_start.png)

画面のスライダー（hidden_1、hidden_2、lerning_rate など）でモデルの形や学習の速さを変えられますが、それは最後の章のお楽しみにして、まず中身を作る側から見ていきます。
