## 点数のままでは困る理由

出力層から出てきた10個の点数は、マイナスもあれば 4 を超えるものもある、バラバラの数です。学習で使うには「全部 0 以上で、合計するとちょうど 1」という確率の形に直したい。そうすれば「正解の数字に確率をいくつ割り当てたか」で答え合わせができます。

この変換がソフトマックス（softmax）です。作り方は2手です。

```
手順1：各点数を exp に通す      → 全部プラスの数になる
手順2：それぞれを合計で割る    → 合計がちょうど 1 になる
```

3個の点数でやってみます。点数が (2, 1, −1) なら、

```
手順1： exp(2) = 7.39   exp(1) = 2.72   exp(−1) = 0.37
        合計 = 10.48
手順2： 7.39 ÷ 10.48 = 0.71
        2.72 ÷ 10.48 = 0.26
        0.37 ÷ 10.48 = 0.03
```

確率 (0.71, 0.26, 0.03) ができました。全部プラスで合計 1。点数の大小関係はそのまま残り、差は exp のおかげで強調されます。ただ合計で割るだけと違って、マイナスの点数があっても壊れないのが exp を通す理由です。

## 表が小さいことへの対策

第5章の exp の表は −10 から 10 までしかありません。点数が 10 を超えると表の端でつぶされて、確率が壊れます。

そこで、exp に通す前に、全点数からいちばん大きい点数を引きます。

```
手順0：10個の点数の最大値を見つけ、全点数から引く
```

こうすると点数の最大値はちょうど 0 になり、残りは全部マイナスになるので、表の範囲に必ず収まります。そして出来上がる確率は引く前と同じです。分子も分母も同じだけ小さくなるので、割り算の結果が変わらないからです。さっきの例で確かめると、(2, 1, −1) から 2 を引いて (0, −1, −3) にしてから計算しても、(0.71, 0.26, 0.03) が出てきます。

最大値を探すブロックがこれです。10個を順に見て、大きいものを覚えていくだけの地道なループです。

## ソフトマックス本体のブロック

![s4_ソフトマックスを適用の定義](/images/backpropagation_on_scratch/fwd/s4.png)

上から順に、

1. 最大値を探す（`u_max_output_z`）
2. 1つ目のループ：各点数から最大値を引き、exp の表を引いて `s4_exp_vals` にため、合計 `s4_exp_sum` も作る
3. 2つ目のループ：ためた値を合計で割って、`activations` の出力層の場所（209番目から10個）に書き込む

これで `activations` の最後の10個が「0 の確率、1 の確率、……、9 の確率」になりました。順伝播はここまでで完成です。

ちなみにこの `s4` ブロックには、作者が作ったとき、存在しない場所を読んでしまうバグが1つ埋まっていました。学習が全く進まない原因になったのですが、この画面を眺めていても気づけますか。答え合わせは第14章でやります。

## ここまでの通し確認

画像を1枚流すと、こうなります。

```
画像196個 → 隠れ層1（8個、シグモイド）
          → 隠れ層2（4個、シグモイド）
          → 出力の点数10個
          → ソフトマックス
          → 確率10個（合計1）
```

重みがまだ乱数なので、いま流すと確率はどの数字もだいたい 0.1、つまり「全然わからない」という答えが返ります。ここからが本番です。まず教材を用意します。
